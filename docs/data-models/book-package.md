# Book Package

The book package is the **output of the prep stage** and the **input to the TTS stage**. It is a voice-agnostic bundle that contains everything needed to produce an audiobook, except the voice itself.

## Structure

```
s3://bucket/packages/{job_id}/
├── book.epub              ← Clean, Kindle-ready EPUB
├── script.json            ← Base narrator script
├── page-ledger.json       ← Page parity manifest
├── cover.jpg              ← Cover art (extracted, found, or placeholder)
├── metadata.json          ← Book metadata (title, author, subject, genre, etc.)
├── llm-analysis.json      ← LLM analysis (subject, tone, style recommendations)
├── images/                ← Extracted images (if any kept)
│   ├── figure-001.png
│   └── ...
└── manifest.json          ← Package metadata
```

## Cover Art

The cover art is part of the book package, produced by the prep worker:

1. **Extract from source**: Try to extract the cover image from the PDF/EPUB
2. **Search the internet**: If not found in the source, search for the book's cover online (by title + author)
3. **Flag for generation**: If not found, flag the book package as needing cover art. The cover can be:
   - Uploaded manually by the user
   - Generated by AI (in a future stage)

The cover art is stored as `cover.jpg` in the book package.

## Metadata

The `metadata.json` file contains the book's metadata, extracted or found by the prep worker:

```json
{
  "title": "The Castle",
  "author": "Jane Doe",
  "subject": "A mystery set in a remote castle",
  "genre": "Mystery",
  "description": "A tale of mystery and intrigue...",
  "language": "en",
  "year": "2026",
  "isbn": null,
  "publisher": null
}
```

**Metadata extraction strategy:**
1. Extract from PDF/EPUB metadata (PyMuPDF `doc.metadata`, XMP stream)
2. Extract ISBN from first 10-15 pages, look up metadata via isbnlib (Google Books, Open Library)
3. First-page layout analysis (largest font = title, subsequent text = author)
4. Internet search by title + author (if extraction fails)

Metadata extraction is best-effort. The user submits a PDF, and the pipeline extracts or finds metadata.

## EPUB Requirements

The EPUB in the book package must be:

- Valid EPUB 3.0+
- Kindle-compatible (no proprietary extensions)
- Clean structure (proper `<nav>`, `<section>`, headings)
- All images embedded and referenced correctly
- No scanner artifacts or garbage content
- Table of contents matching the actual chapter structure

## Validation

Before a book package is marked complete, the prep worker must validate:

1. **Page parity**: Page ledger accounts for every page in the source
2. **EPUB validity**: EPUB opens without errors, valid XML, proper structure
3. **Script validity**: All segments have valid source references
4. **Cross-references**: 
   - Every `source_ref` in the script exists in the page ledger
   - Every page marked `kept` in the ledger appears in the EPUB or script
   - Chapter structure is consistent across all three artifacts

If any validation fails, the job is marked `failed` with detailed error messages.

## Consumption by TTS Workers

TTS workers consume the book package as follows:

1. Download the package from S3
2. Read `manifest.json` to understand the package
3. Read `script.json` to get the text to narrate
4. Read `cover.jpg` for the cover art
5. Read `metadata.json` for the book metadata
6. Apply the voice recipe and performance style to each segment
7. Produce the audiobook package

The TTS worker does **not** need the EPUB or page ledger for audio generation. Those are for the reader and the audit trail, respectively.
